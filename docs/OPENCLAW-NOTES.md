# 从 OpenClaw 借鉴了什么

本项目在扩展 provider 时研究了 OpenClaw 的公开 channel 设计与文档。

借鉴的主要是架构思想，而不是代码：

- 每个渠道独立封装认证、发送和平台限制。
- 同一渠道可有多种认证/投递模式，例如 webhook 与 bot/app API。
- Secret 通过运行环境注入，不进入普通配置和日志。
- 平台能力不同，不强行假设所有渠道都支持相同特性。
- 对需要常驻状态、本地桥接或二维码会话的渠道，明确区分于无服务器 HTTP outbound 渠道。

`chatgpt-relay` 的边界比 OpenClaw 小得多：这里只需要**一次性 outbound 通知**，没有 Gateway、入站事件、会话路由、媒体状态机、群聊策略或机器人循环保护。

因此实现全部按本项目需求重新编写，只保留对公开平台 API 的最小调用。
